Magpie Privacy Policy

Effective date: October 10, 2026. This policy applies to Magpie for Android, package com.agle.app. Support email and developer contact: fanghong512@gmail.com.

What Magpie does

Magpie is a local-first Android application for browsing and managing Eagle-format image and media asset libraries. It can connect to storage selected by you, including local storage, SMB, WebDAV, Google Drive and OneDrive. Magpie does not require a Magpie account and does not operate a backend that receives your library files or OAuth tokens.

Data processed on your device

To provide the library features, Magpie processes the files and metadata in the storage you connect or select. This can include asset files, thumbnails, folder names, tags, ratings, annotations, comments, source links and other library metadata. The app also stores settings, connection information, OAuth tokens and cached library data on your device. OAuth tokens and storage credentials are stored using encrypted preferences backed by Android Keystore.

Google user data

When you add Google Drive, Magpie uses Google authorization and the Google Drive API to locate existing Eagle-format library folders, list files, download assets and metadata, and write library or asset changes requested by you. Magpie requests https://www.googleapis.com/auth/drive because the existing-library workflow must discover and update files that were not created by Magpie. This permission can allow access to all files in the authorized Drive account; Magpie uses it for the library workflow and optional user-requested processing described in this policy.

Google user data is transferred directly between the app and Google Drive. Magpie does not sell, advertise with, or use Google user data for unrelated purposes, and does not transfer Google user data to a Magpie-operated server. Google user data is not used to train a general-purpose AI model. You can revoke access at any time in your Google Account third-party connections settings or by signing out in Magpie.

Optional AI and visual search

When you explicitly start AI processing, the selected images and/or text are sent to the model endpoint configured by you, using the API key configured by you. When you explicitly start visual search, the selected image is sent to the search provider shown in the app. These providers may process or retain data under their own policies. Do not use these optional features with confidential content unless you accept the provider's terms.

This also applies to assets downloaded from a connected Google Drive library: selected original images or thumbnails and task-specific text or metadata can be sent to your configured AI provider for analysis, naming, tagging, description, rating or folder organization. Selected images can be sent to Pinterest for visual search. These actions are optional; connecting Google Drive alone does not start AI processing or visual search. Google OAuth tokens are not sent to AI or visual-search providers. Do not send Google Drive data to a provider whose terms permit using it to train general-purpose AI models.

Magpie's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Magpie is not an AI image-generation service and does not use Google APIs for AI-generated non-consensual intimate imagery.

Sharing and retention

Magpie sends data only to the storage provider or optional processing provider needed for an action you request. Source files remain in your storage until you delete or change them there. Device settings, encrypted credentials and caches remain until you remove them through Magpie or clear the app's Android data. Clearing app data does not delete source files in remote storage.

Your choices and deletion

You may use local libraries without Google Drive, decline Google authorization, sign out, revoke Google access in your Google Account, or stop using optional AI and visual-search features. To request help about information sent directly to the developer, email fanghong512@gmail.com. Do not include passwords, OAuth codes, refresh tokens or API keys in support messages.
